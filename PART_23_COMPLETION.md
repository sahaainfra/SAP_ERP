### 2. Approval Centre Service (`approval-centre-service.ts`)

**Core Features:**
- **Queue Management** — Fetch, filter, group, and sort approval queue
- **Detail Context** — Load full decision context with budget impact, comparison, risk flags
- **Six Decision Actions:**
  - Approve — Validates authority against DB amount
  - Reject — Requires reason
  - Return for correction — Pauses SLA clock
  - Forward — To another authorized user
  - Approve with conditions — Attaches mandatory conditions
  - Request information — Creates thread without returning document
- **Bulk Approval** — Maximum 20 items (5 on phones), excludes over-limit and risk-flagged items
- **Out-of-Office** — Delegation with substitute, capped at substitute's authority
- **Queue Counts** — Real-time counts for shell bar badges

**Business Rules Enforced:**
- **APR-01** — Full decision context shown server-side (budget impact, comparison, risk flags, overrides, history)
- **APR-02** — Overrides always shown (no blind approvals)
- **APR-03** — Bulk approval: max 20 items, each evaluated individually, one confirmation with total
- **Authority Validation** — Re-validated against DB amount, not request payload

### 3. Exception Centre Service (`exception-centre-service.ts`)

**Core Features:**
- **Exception Queue** — Fetch, filter, sort by impact/severity/age
- **Four Categories:**
  - Financial — Budget exceeded, receivables 90+, duplicate payments
  - Operational — Negative stock, BOQ exceeded, consumption variance
  - Compliance — SoD violations, expired documents, failed tests
  - Process — Approval SLA breach, stalled workflows, overdue tasks
- **Management Actions:**
  - Assign owner and target date
  - Resolve with explanation
  - Accept as known exception with justification and expiry
- **Trend Analysis** — Raised vs resolved over time by category

**Business Rules Enforced:**
- **EXC-01** — Exceptions closed by human with explanation, never auto-closed by time
- **EXC-02** — Every exception names responsible party and proposed actions
- **Ranking** — By impact value, then severity, then age

### 4. Task Centre Service (`task-centre-service.ts`)

**Core Features:**
- **Task Management** — Create, complete, reassign, update due date
- **Seven Task Sources:**
  - Manual — Created by users
  - System — Generated by events (e.g., consumption variance)
  - Follow-up — Created from approval conditions
  - Exception — Linked to exceptions
  - Condition of Approval — Mandatory follow-up actions
- **Four Views:**
  - List — Traditional table view
  - Board — Kanban-style columns
  - Calendar — Date-based view
  - Timeline — Chronological view
- **Recurring Tasks** — Cron-based recurrence with automatic generation
- **Resolution Validation** — Configurable requirements (min length, pattern)

**Business Rules Enforced:**
- **Reassignment** — Transfers work but grants no permission
- **Overdue Changes** — Requires reason for due-date changes
- **Resolution** — Validated against requirements before completion

### 5. Notification Centre Service (`notification-centre-service.ts`)

**Core Features:**
- **Multi-Channel Delivery** — IN_APP, EMAIL, PUSH, SMS
- **Priority Levels** — LOW, MEDIUM, HIGH, CRITICAL
- **Grouping & Digesting** — Similar notifications grouped after threshold (default 5)
- **Quiet Hours** — Configurable per user (e.g., 10 PM - 7 AM)
- **Rate Limiting** — Maximum 10 notifications per hour (except CRITICAL)
- **Auto-Expiry** — Notifications expire when underlying item is resolved
- **Escalation** — Notifies target and informs original assignee

**Business Rules Enforced:**
- **Channel Preferences** — Respects user's enabled channels
- **Quiet Hours** — Non-critical notifications queued during quiet hours
- **Rate Limit** — Prevents notification spam
- **CRITICAL Override** — Critical notifications bypass quiet hours and rate limits

### 9. API Endpoints

| GET | `/api/dx/v1/approvals/history` | This user's decision history |

| POST | `/api/dx/v1/tasks` | Create task |
| PUT | `/api/dx/v1/tasks/{id}` | Update task |
| POST | `/api/dx/v1/tasks/{id}/complete` | Complete with note |
| POST | `/api/dx/v1/tasks/{id}/reassign` | Reassign |
| GET | `/api/dx/v1/exceptions` | Exception list for permitted scope |
